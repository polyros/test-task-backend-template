# Code Review

## Найденные проблемы

### 1. SQL Injection

- **Файл:** app/api/users.py
- **Строка:** 40
- **Описание:** Прямое внедрение пользовательского ввода в SQL запрос через f-string
- **Потенциальные последствия:** Злоумышленник может получить доступ к любым данным БД, удалить таблицы, изменить данные
- **Рекомендация:** Использовать параметризованные запросы или ORM

### 2. Логирование пароля

- **Файл:** app/api/users.py
- **Строка:** 23
- **Описание:** Пароль пользователя пишется в лог в открытом виде
- **Потенциальные последствия:** Компрометация паролей через логи, нарушение 152-ФЗ
- **Рекомендация:** Никогда не логировать чувствительные данные

### 3. Хранение пароля без хеширования

- **Файл:** app/api/users.py
- **Строка:** 27
- **Описание:** Пароль сохраняется в БД как есть, без хеширования
- **Потенциальные последствия:** При утечке БД все пароли скомпрометированы
- **Рекомендация:** Использовать bcrypt или argon2 для хеширования

### 4. Отсутствие валидации входных данных

- **Файл:** app/api/users.py
- **Строка:** 18
- **Описание:** Параметр `data: dict` без Pydantic схемы
- **Потенциальные последствия:** Нет проверки типов, обязательных полей, форматов. KeyError при отсутствии полей
- **Рекомендация:** Создать Pydantic модели для request/response

### 5. Блокирующий HTTP в async функции

- **Файл:** app/api/users.py
- **Строка:** 77
- **Описание:** Синхронный `requests.get()` в async endpoint
- **Потенциальные последствия:** Блокировка event loop, деградация производительности всего приложения
- **Рекомендация:** Использовать httpx или aiohttp

### 6. N+1 проблема

- **Файл:** app/api/users.py
- **Строки:** 54-60
- **Описание:** Для каждого order выполняется отдельный запрос, хотя данные уже есть в user.orders
- **Потенциальные последствия:** При 100 заказах = 101 запрос к БД, тормоза
- **Рекомендация:** Использовать данные из relationship напрямую

### 7. Глобальный счётчик с race condition

- **Файл:** app/api/users.py
- **Строки:** 14, 21
- **Описание:** Глобальная переменная `request_counter` изменяется без синхронизации
- **Потенциальные последствия:** Некорректный подсчёт при параллельных запросах
- **Рекомендация:** Вынести в Redis или использовать Lock

### 8. Неправильные HTTP статусы

- **Файл:** app/api/users.py
- **Строки:** 51, 75
- **Описание:** При ошибке возвращается 200 OK с телом `{"error": "..."}` вместо 404
- **Потенциальные последствия:** Клиенты не смогут корректно обработать ошибки
- **Рекомендация:** Использовать HTTPException с правильным status_code

### 9. Hardcoded DATABASE_URL

- **Файл:** app/database.py
- **Строка:** 4
- **Описание:** URL базы зашит в код
- **Потенциальные последствия:** Нельзя использовать разные БД для dev/prod/test
- **Рекомендация:** Читать из переменных окружения

## Внесённые исправления

| Проблема | Файл | Что исправлено |
|----------|------|----------------|
| SQL Injection | app/api/users.py | Заменил raw SQL на ORM запрос с filter |
| Логирование пароля | app/api/users.py | Убрал пароль из лога |
| Хранение пароля | app/api/users.py | Добавил хеширование через passlib |
| Валидация | app/api/users.py, app/schemas.py | Создал Pydantic схемы |
| Блокирующий HTTP | app/api/users.py | Заменил requests на httpx async |
| N+1 | app/api/users.py | Убрал лишние запросы, использую relationship |
| Race condition | app/api/users.py | Убрал глобальный счётчик (для прода нужен Redis) |
| HTTP статусы | app/api/users.py | Добавил HTTPException с 404 |
| Hardcoded URL | app/database.py | Чтение через os.environ |
